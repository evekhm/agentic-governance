Episode 01

Securing the Agent-to-Database Connection

November 2026 · about 90 minutes in full

This episode follows a single request: a customer asks an agent, “What is the status of my order #104?” It starts from the top-level picture of a user, an agent and a database, and drills down hop by hop to the low-level details: which token travels on each call, which SQL runs, and whose identity the database sees. At each level it shows what can go wrong and which guardrail prevents it, so that the detailed architecture at the end still reads as one picture.

What the stages add

  • Tool boundary. Fixed, parameterized queries replace model-written SQL.
  • Identity. The agent gets its own workload identity and exchanges the user’s token for a short-lived, narrowly scoped one.
  • Database. The engine enforces row- and column-level security on every query.
  • Gateways. Ingress and egress proxies authorize each call and screen content in both directions.
  • Network. Private connectivity and a data perimeter remove the routes out.
  • Writes. A human approves each change, and stored procedures make it idempotent.
  • Audit. One trace follows a request across every hop, backed by a kill switch.
  • Mapping. Each control is mapped to the OWASP Agentic Top 10 (2026) and LLM Top 10 (2025).

Episode 02

A Mental Model for Designing Agentic Systems

November 2026 · about 15 minutes

This episode takes one design task: a system with three agents that detects a failed deployment, suggests a fix, and opens a pull request. The first drawing is three agents in a row, and it looks finished. The episode asks what that drawing leaves out, and answers with one skeleton and twelve questions that can be reused on other systems of this kind.

What the questions cover

  • Before drawing. What starts the work, how much of it there is, and what has to happen in seconds without a model.
  • Plumbing. The queue, duplicates, many failures at once, and a worker that dies halfway.
  • Agents. Which steps need a model and which are code, what passes between them, and who owns the state.
  • Safety and launch. Untrusted input, sandboxing, and switching the system on in stages.
